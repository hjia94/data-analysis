LAPD HDF5 data schema

How a Large Plasma Device (LAPD, UCLA BaPSF) data-run file is organised: what data it holds, where, and which metadata is designed to be there.

Background

Each data run is saved as one HDF5 file. A run is a sequence of shots, where each shot is one plasma discharge. On every shot, the digitizers record a waveform from each wired channel. Between shots, a motorised probe drive can move a probe, so each shot also has a recorded probe position. A run can scan a line or a plane, taking several shots at each position.

Two acquisition systems write these files, so there are two layouts:

  • Layout 1 – bapsflib: written by the BaPSF LabVIEW DAQ and its C translator. The digitizer is an SIS 3302 crate. The file also holds the machine-state record (MSI). It is named after bapsflib, the BaPSF Python library that reads it. The example is the Mar-2026 run 01-mach-p29-xline-bias.hdf5.
  • Layout 2 – pydaq: written by the Python LAPD_DAQ repo. The digitizers are LeCroy oscilloscopes. The example is the Jun-2026 run 00-He-800G-bias40V-LP-p29-line_2026-06-10.hdf5.

Every name, shape and attribute below was read from those two files. Shapes use these symbols:

  • nshot: shots in the run
  • nt: samples per trace
  • nmsi: rows in the machine-state record, which need not equal nshot

Things to know

  • The k in configurations[k] is not the board number. Find each one's slot by pairing @SIS crate config indices with @SIS crate slot numbers, then look the slot up in the table above. In the example run, configurations[1] is slot 11, which is board 4.
  • Only channels with @Enabled C = 'TRUE' recorded data. Disabled channels can still carry a Data type label left over from a previous setup.
  • Waveform rows are numbered from 0, but shot numbers start at 1. The Shot number field in headers gives each row's shot number. That same number links the row to bmotion_positions.
  • MSI/ is not one row per digitizer shot. The example run has 2 MSI rows against 405 digitizer shots. Match rows by Shot number, not by position.

Things to know

  • Scope group names are lowercase in the file (lpscope) but mixed-case in experiment_config (LPScope_C2).
  • [channels] can list channels that were never saved. In the example run, LPScope_C1 is configured but lpscope/shot_*/ has no C1_data. The file's own Cn_description attributes and datasets show what was actually recorded.
  • shot_N groups sort as text (shot_1, shot_10, shot_100, …), not as numbers. Sort them by N.
  • In multi-probe runs, each probe's positions_array spans the whole run. Rows for shots belonging to the other probe have shot_num = 0; treat those as padding. Otherwise, shot_num = N links a position row to shot_N/.
  • The interferometer holds only two traces per channel: the ones nearest the run's first and last shots, recorded in @merged shot numbers. They describe the run as a whole, not each shot.
  • Waveform datasets are compressed with lzf (built into h5py) or Blosc2. Reading Blosc2 needs the hdf5plugin package.
